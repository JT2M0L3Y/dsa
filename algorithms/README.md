# Algorithms

An algorithm is a finite procedure for solving a problem. This catalog focuses on interview-relevant ideas, preconditions, complexity, and representative implementations; it is selective rather than encyclopedic.

## How to use this catalog

For each problem, identify the input constraints and required operations before choosing an algorithm. Check preconditions (for example, non-negative edge weights for Dijkstra), then account for both time and auxiliary space. A named algorithm can use several patterns and data structures; the cross-links explain those relationships.

Advanced examples such as Held–Karp are presented as pseudocode where a full implementation would obscure the state definition. There is no curated problem list.
